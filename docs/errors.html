Error Handling

All errors return consistent JSON responses with helpful messages to help you debug and handle issues gracefully.

⚠️ Remember: Always implement proper error handling in your applications. Network issues, rate limits, and invalid parameters are normal parts of API integration.

Error Response Format

When an error occurs, the API returns a JSON object with detailed information:

{
  "error": {
    "code": "invalid_parameters",
    "message": "The request parameters are invalid",
    "details": {
      "field": "work_id",
      "reason": "Work ID must be a valid UUID"
    },
    "request_id": "req_2a7f8c3e1b9d4f6"
  }
}

Error Fields

error.code A machine-readable error code for programmatic handling
error.message Human-readable description of what went wrong
error.details Additional context (field name, specific reason, etc.)
error.request_id Unique identifier for debugging (include in support requests)

HTTP Status Codes

PIGMENT v6 uses standard HTTP status codes to indicate the success or failure of requests:

400 Bad Request Invalid parameters or malformed request
401 Unauthorized Missing or invalid API key (check X-API-Key header)
403 Forbidden API key valid but lacks permission (e.g., accessing another user's work)
404 Not Found Resource doesn't exist (check work_id, user_id, etc.)
409 Conflict Resource already exists (e.g., duplicate email in /v1/users)
422 Unprocessable Entity Validation failed (e.g., email format invalid)
429 Too Many Requests Rate limit exceeded (see Rate Limits)
500 Internal Server Error Something went wrong on our end — try again later
503 Service Unavailable API temporarily offline (maintenance or overload)

Common Error Codes

Authentication Errors

missing_api_key No X-API-Key header provided
invalid_api_key API key format is invalid or key not found
expired_token JWT token has expired (if using Bearer auth)

Works Errors

work_not_found The specified work_id doesn't exist
invalid_genome The .pg genome content is malformed
feature_extraction_failed Could not extract 16D features from genome

Evolution Errors

evolution_failed Genetic algorithm process failed (rare)
invalid_steps steps parameter must be between 1-2000
invalid_mutation_rate mutation_rate must be between 0.1-5.0

Kinship Errors

insufficient_data Need at least 2 works to compute kinship
feature_mismatch Feature vectors have incorrect dimensions

Prompt Errors

prompt_too_long Prompt exceeds 500 characters
claude_unavailable Claude API temporarily unavailable (fallback used)

Error Handling Examples

JavaScript Error Handling 
async function safeApiCall() {
    try {
        const response = await fetch('https://pigment-api.onrender.com/v1/works', {
            headers: { 'X-API-Key': 'your-key' }
        });
        
        if (!response.ok) {
            const errorData = await response.json();
            
            // Handle specific error codes
            switch (errorData.error?.code) {
                case 'invalid_api_key':
                    console.error('API key invalid — regenerate from /v1/users');
                    break;
                    
                case 'work_not_found':
                    console.error('Work ID not found — check your ID');
                    break;
                    
                case 'rate_limit_exceeded':
                    const retryAfter = response.headers.get('Retry-After');
                    console.log(`Rate limited. Wait ${retryAfter}s`);
                    // Implement exponential backoff
                    await new Promise(r => setTimeout(r, retryAfter * 1000));
                    return safeApiCall(); // Retry
                    
                default:
                    console.error(`API Error: ${errorData.error?.message}`);
            }
            return null;
        }
        
        return await response.json();
        
    } catch (networkError) {
        console.error('Network error — check your connection');
        return null;
    }
}
import requests
import time

def safe_api_call():
    try:
        response = requests.get(
            'https://pigment-api.onrender.com/v1/works',
            headers={'X-API-Key': 'your-key'}
        )
        
        if response.status_code != 200:
            error_data = response.json()
            error_code = error_data.get('error', {}).get('code')
            
            if error_code == 'invalid_api_key':
                print('API key invalid — regenerate from /v1/users')
                
            elif error_code == 'work_not_found':
                print('Work ID not found — check your ID')
                
            elif response.status_code == 429:
                retry_after = int(response.headers.get('Retry-After', 30))
                print(f'Rate limited. Waiting {retry_after}s')
                time.sleep(retry_after)
                return safe_api_call()  # Retry
                
            else:
                print(f"API Error: {error_data.get('error', {}).get('message')}")
            return None
            
        return response.json()
        
    except requests.exceptions.ConnectionError:
        print('Network error — check your connection')
        return None

Handling Network Errors

Network issues can occur. Always implement retry logic with exponential backoff:

async function fetchWithRetry(url, options, maxRetries = 3) {
    for (let i = 0; i < maxRetries; i++) {
        try {
            return await fetch(url, options);
        } catch (err) {
            if (i === maxRetries - 1) throw err;
            
            // Exponential backoff: 1s, 2s, 4s...
            const waitTime = Math.pow(2, i) * 1000;
            console.log(`Retry ${i + 1}/${maxRetries} in ${waitTime}ms`);
            await new Promise(r => setTimeout(r, waitTime));
        }
    }
}

Debugging Tips

  • Check the request_id — include this when contacting support
  • Verify your API key — ensure it's in the X-API-Key header
  • Validate work_ids — they should be UUID format
  • Monitor rate limits — check X-RateLimit-Remaining headers
  • Test with curl first — isolate client-side issues
