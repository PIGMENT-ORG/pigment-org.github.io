Frequently Asked Questions

Everything you need to know about the PIGMENT v6 API.

General

What is PIGMENT?

PIGMENT is an open-source API that uses genetic algorithms to evolve artwork. Each artwork is represented as a .pg genome file — a collection of colored polygons with opacity and position data. Through mutation and selection, these genomes evolve to match target images or create new styles based on AI prompts.

Unlike traditional image generation APIs, PIGMENT focuses on the evolution process itself, storing the genome rather than rendered images. This allows for kinship tracking, ancestry analysis, and infinite variations.

How does the evolution work?

The system uses 7 mutation operators:

  • scale — Resize polygons
  • translate — Move polygons
  • color — Shift RGB values
  • opacity — Change transparency
  • rotate — Rotate polygons
  • addpoint — Increase polygon complexity
  • intelligent — Use best-performing operator

Each mutation's success is tracked, and operator probabilities adapt in real-time based on what works best for the current context (sky/face/ground) and phase (explore/refine/polish).

What's a .pg genome file?

A PIGMENT Genome file (.pg) is a human-readable text format that completely describes an artwork:

-- PIGMENT Genome v6.0.0
-- @fitness 87.3
-- @generation 1542

canvas { width: 400 height: 400 }

palette {
  c0: #ff3366
  c1: #33ff99
}

layer evolved {
  zone poly_0 {
    color: palette.c0
    opacity: 0.8
    points: 120,140 180,120 160,200
  }
}

This format stores everything needed to reconstruct and continue evolving the artwork.

Pricing & Limits Always Free

Is PIGMENT free?

Yes! PIGMENT is completely free and open-source. There are no paid tiers, no credit cards required, and no hidden costs. The entire platform is designed to be accessible to everyone — artists, researchers, students, and hobbyists.

If you need higher rate limits or dedicated support, please contact us for enterprise options.

What are the rate limits?

Current rate limits are generous and designed for fair usage:

  • 60 requests per minute (free tier)
  • Concurrent evolution jobs: Limited by your deployment (Layer 2 = sync, Layer 3/4 = configurable)
  • Maximum steps per evolution: 2000 (configurable in code)

Rate limit status is included in response headers: X-RateLimit-Limit, X-RateLimit-Remaining, X-RateLimit-Reset.

How long is data stored?

Your artworks are stored in your own database (SQLite or PostgreSQL) and persist indefinitely. There's no automatic deletion — you control your data.

The public gallery shows all works from all users, but you can delete your works anytime via the DELETE /v1/works/{id} endpoint.

Technical

How do I get an API key?

Simply make a POST request to the /v1/users endpoint with your email:

curl -X POST https://pigment-api.onrender.com/v1/users \
  -H "Content-Type: application/json" \
  -d '{"email": "your@email.com"}'

The response includes your API key starting with pigment_. No signup form, no approval process — instant access!

What image formats are supported?

For input (when loading images into the frontend):

  • JPEG/JPG
  • PNG
  • GIF (first frame)
  • WebP
  • BMP

For output (what the API stores):

  • .pg genome files (native format)
  • PNG exports available via frontend
  • SVG exports available via Genome Viewer
What are the size limits?

Your frontend enforces reasonable limits:

  • Image dimensions: Scaled to fit within ~400px (configurable)
  • Polygon count: 10-300 (default 50)
  • Genome file size: Proportional to polygon count — a 50-polygon genome is ~2KB

There's no hard file size limit — performance will degrade gracefully with very large genomes.

How fast is evolution?

Performance depends on your setup:

  • Browser (Layer 1): 500-1000 steps/second
  • Layer 2 (server.py): 1000-2000 steps/second (pure Python)
  • Layer 3/4 (FastAPI): 2000-5000 steps/second (async + workers)

A typical evolution of 500 steps takes 1-2 seconds on the server.

Kinship System

How does kinship work?

Each artwork has a 16-dimensional feature vector extracted from its genome. Kinship calculates similarity using a weighted combination:

  • 40% Visual features — RGB means, standard deviations, entropy
  • 30% Generational distance — How many generations apart
  • 30% Structural features — Polygon count, opacity, point counts

Relationships are classified as parent/child, sibling (≥82% similarity), cousin (65-81%), or similar (45-64%).

Can I visualize kinship trees?

Yes! Use our official kinship visualization library:

<script src="https://pigment-org.github.io/js/kinship-viz.js"></script>
<div id="kinship-tree"></div>

const data = await fetch('https://pigment-api.onrender.com/v1/kinship', {
    method: 'POST',
    headers: { 'X-API-Key': 'your-key' },
    body: JSON.stringify({ work_id: 'work_123' })
});

KinshipViz.render('kinship-tree', data);

AI Prompts

How do AI prompts work?

The /v1/prompt endpoint uses Claude API (with local fallback) to translate natural language into structured mutation plans:

  • "make it glitchy" → glitch_colors + chaos + boost_contrast
  • "organic feel" → organic_spread + smooth + saturate
  • "darker, more void" → void_crush + darken + remove_polygons

If Claude is unavailable, intelligent keyword matching provides reasonable fallback behavior.

Do I need an Anthropic API key?

No! The system works perfectly with local keyword matching. Claude integration is optional — if you add ANTHROPIC_API_KEY to your environment, prompts will be processed by Claude; otherwise, the built-in fallback handles everything locally.

Deployment

Can I host PIGMENT myself?

Absolutely! PIGMENT is open-source and designed for self-hosting:

  • Layer 2: Pure Python, no dependencies — run with python3 server.py
  • Layer 3: FastAPI + PostgreSQL + Redis — Docker Compose included
  • Layer 4: Add Claude API, FAISS, and WebSockets

Clone from GitHub and deploy anywhere — Render, DigitalOcean, or your own server.

Will my Render deployment sleep?

On the free tier, Render spins down after 15 minutes of inactivity. To keep your API awake 24/7, use a monitoring service like UptimeRobot to ping your /health endpoint every 5-10 minutes. This uses your free 750 hours/month without incurring charges.
