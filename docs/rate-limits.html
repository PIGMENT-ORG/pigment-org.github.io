Rate Limits

Understand our rate limiting policy to build reliable applications. Rate limits help ensure fair usage and API stability for all users.

ℹ️ Note: Rate limits are currently generous on the free tier. These limits may be adjusted as the platform grows. Always implement proper error handling in your applications.

Current Rate Limits

Based on your API key type and plan, different rate limits apply:

🎨 Free Plan
60 requests/minute
2 concurrent evolution jobs (when using Layer 3/4)

Default for all new API keys from /v1/users

🚀 Enterprise Plan
Custom limits
Unlimited concurrent jobs

Contact us for enterprise access

Rate Limit Headers

Every API response includes headers that show your current rate limit status:

X-RateLimit-Limit: 60          // Your total allowed requests per minute
X-RateLimit-Remaining: 58      // Requests left in current window
X-RateLimit-Reset: 1640995200  // Unix timestamp when limits reset

Example Response with Headers

HTTP/1.1 200 OK
Content-Type: application/json
X-RateLimit-Limit: 60
X-RateLimit-Remaining: 57
X-RateLimit-Reset: 1708531200

{
  "id": "work_abc123",
  "title": "My Artwork"
}

Handling Rate Limits

When you exceed your rate limit, the API returns a 429 Too Many Requests response. Implement exponential backoff to handle this gracefully.

Exponential Backoff Example

JavaScript 
async function makeRequestWithRetry(requestFn, maxRetries = 5) {
    for (let i = 0; i < maxRetries; i++) {
        try {
            return await requestFn();
        } catch (error) {
            // Check if it's a rate limit error (429)
            if (error.status !== 429) throw error;
            
            // Calculate wait time: 2^i seconds with jitter
            const waitTime = Math.pow(2, i) * 1000 + Math.random() * 1000;
            console.log(`Rate limited. Retrying in ${waitTime/1000}s...`);
            
            await new Promise(resolve => setTimeout(resolve, waitTime));
        }
    }
    throw new Error('Max retries exceeded');
}

// Usage
const result = await makeRequestWithRetry(() => 
    fetch('https://pigment-api.onrender.com/v1/works', {
        headers: { 'X-API-Key': 'your-key' }
    })
);

Python Example

import time
import random

def make_request_with_retry(request_func, max_retries=5):
    for i in range(max_retries):
        try:
            return request_func()
        except Exception as e:
            if getattr(e, 'status', None) != 429:
                raise e
            
            wait_time = (2 ** i) + random.random()
            print(f"Rate limited. Retrying in {wait_time:.1f}s...")
            time.sleep(wait_time)
    
    raise Exception("Max retries exceeded")

Concurrent Jobs

Depending on your plan, you can run multiple evolution jobs simultaneously:

  • Free Plan: Up to 2 concurrent jobs
  • Enterprise: Custom limits

Check your active jobs:

# For Layer 3/4 (FastAPI version)
curl -X GET https://pigment-api.onrender.com/v1/jobs \
  -H "X-API-Key: your-key"
📌 Note: If you're using the Layer 2 version (`server.py`), jobs are processed synchronously. The `/v1/jobs` endpoint is only available in the Layer 3/4 FastAPI deployment.

Best Practices

  • Cache responses when possible to reduce API calls
  • Implement exponential backoff with jitter
  • Monitor your usage via response headers
  • Queue requests instead of sending bursts
  • Use WebSocket for real-time updates instead of polling

What Happens When You're Rate Limited?

The API returns:

HTTP/1.1 429 Too Many Requests
Content-Type: application/json
Retry-After: 30

{
  "error": "Rate limit exceeded",
  "message": "You have exceeded your rate limit of 60 requests per minute. Please wait 30 seconds before retrying.",
  "retry_after": 30
}
